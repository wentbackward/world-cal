- 2026-04-28 — fast check `npx tsc --noEmit` — fastest tree-health signal (~1s) that fails on type errors; `npm test` is slower and lives in the gate. Alternative: `npm run build` (~2s) — included as a gate check instead.
- 2026-04-28 — heavy slots 2, memory cap none — vite build is ~2s and nothing is a long-running job today; keep the default. Alternative: capped memory — no shared-host pressure today.
- 2026-04-28 — no ports (empty port_env) — browser-only app, gate needs no servers. Alternative: dev-server ports — not needed for tests/build.
- 2026-04-28 — gate includes `tsc`, `npm test -- --run`, `npm run build`, and `eslint src __tests__` — matches the CI test stage (tests + build) and guards lint regressions. Alternative: tests-only gate — too thin; build catches Rollup/TS split-brain.
- 2026-04-28 — `.pi/` + `scripts/` committed — self-contained checkout, matches the plugin's dogfood layout. Alternative: gitignore `.pi/` — rejected; the files must be present for pi's extension loading and they are versioned project content, not local state.
- 2026-11-21 — Escape cancels the in-progress drag without committing a selection: the hook clears the overlay and discards the drag; it never calls onSelection(null). The committed selection, if any, is still cleared by the app-level Escape handler in App (window keydown), unchanged by this ticket — the spec pins only the drag cancellation, so selection-clearing stays single-sourced in App. Pinned by a jsdom test (drag in progress + committed selection + Escape → overlay cleared, drag discarded, committed selection gone). Alternative: the hook calls onSelection(null) on Escape — rejected as duplicate selection handling.
- 2026-11-21 — pointercancel commits the drag (same as pointerup), including in-grid cancels, not aborts — the spec's release sentence (pointerup/pointercancel) is the grid-level contract; keeping the whole release path consistent. The spec's manual checklist describes pointer-cancel as a cancel mid-drag; the tests deliberately pin commit behaviour and document the divergence. Alternative: in-grid cancel aborts — rejected as inconsistent with the spec sentence. Pinned by a jsdom test asserting the in-grid cancel commits.
- 2026-11-21 — setPointerCapture is guarded (try/catch) — jsdom and older browsers lack it; window-level listeners are the primary outside-grid path. Alternative: hard-require capture — rejected (breaks jsdom and fall-backs).
- 2026-11-21 — no `touch-action: none` on the grid — styles/layouts/copy unchanged is a scope boundary (#1); touch drag relies on capture + window listeners, operator verifies touch in manual sign-off. Alternative: add the CSS now — rejected as out-of-scope style change.
- 2026-11-21 — a drag is bound to its initiating pointerId for the whole drag: pointerdown/move/up/cancel from any other pointer are ignored (including pointerdowns flagged isPrimary), only the initiating pointer's release commits, and window pointerup/pointercancel events must match the active pointerId — a second finger tap mid-drag no longer steals the drag (previously its release committed the wrong hour-10 tap over the in-progress region). Alternative: guard only on isPrimary — rejected; the flag does not identify the initiating pointer, so a second pointer can still reset state.
- 2026-11-21 — the window keydown Escape handler ignores events already defaultPrevented by an earlier listener and events whose target is an input/textarea — an Escape aimed at an input (mid-drag, typing) or an already-handled Escape cancels neither the drag nor the overlay; it is the input/handler that owns it. Alternative: unconditional Escape cancel — rejected as surprising while typing in the date input.
